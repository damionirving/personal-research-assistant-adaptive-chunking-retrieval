# Infrastructure

This directory contains the AWS CDK app for the current deployed MVP.

It defines:

- CloudFormation stack generated by CDK.
- S3 document bucket used by the persistence backend for documents, memory, and vector snapshots.
- Lambda function for the FastAPI app through Mangum.
- API Gateway REST API.
- Cognito user pool, app client, Hosted UI domain, and Hosted UI branding.
- Lambda execution role with CloudWatch Logs, S3 read/write permissions, and Bedrock model invocation permissions.
- CloudWatch dashboard and alarms for operational cost and reliability visibility.
- Runtime environment variables.
- CloudFormation outputs for the API URL, document bucket, Cognito, and GitHub OIDC deployment marker.

It does not define AgentCore.

## Install CDK Dependencies

```bash
cd infra
python -m pip install -r requirements.txt
```

## Synthesize CloudFormation

```bash
cd infra
cdk synth
```

## Deploy

```bash
cd infra
cdk deploy
```

The CDK app bundles the repository root into a Lambda asset and installs `requirements-lambda.txt` into that asset.

By default, the stack imports the retained Cognito pool `us-east-1_IxEu5C7oJ`,
then creates its app client and Hosted UI domain against that pool. Override
`cognito_user_pool_id` or `cognito_domain_prefix` with CDK context when using a
different existing pool or domain prefix.

The Cognito Hosted UI color treatment is defined in `pra_infra/stack.py` as a `CfnUserPoolUICustomizationAttachment`. The app client uses authorization code grant with PKCE, 1-hour ID/access tokens, and 30-day refresh tokens. Deploy the stack again after branding, callback URL, OAuth flow, or token lifetime changes.

The deployed Lambda sets `PRA_PERSISTENCE_BACKEND=s3` and stores document and memory JSON snapshots under the configured S3 prefix.

The deployed Lambda sets `PRA_LLM_PROVIDER=bedrock` and uses two deterministic routes:

- Simple answers use `google.gemma-3-12b-it`, with `amazon.nova-lite-v1:0` as a request-scoped fallback after exhausted retryable failures.
- Higher-value reasoning uses `google.gemma-4-31b` through the Bedrock Mantle OpenAI-compatible endpoint, with `mistral.ministral-3-14b-instruct` as a request-scoped Bedrock Runtime fallback after exhausted retryable failures.

The Mantle client obtains a short-lived bearer token with the Lambda execution role; no Mantle API key is stored. CDK grants `bedrock-mantle:CreateInference` on project resources and `bedrock-mantle:CallWithBearerToken`. RAGAS workers remain isolated on `google.gemma-3-12b-it` and do not use either normal-chat fallback chain. Override the corresponding `bedrock_simple_model_id`, `bedrock_simple_fallback_model_id`, `bedrock_reasoning_model_id`, or `bedrock_reasoning_fallback_model_id` CDK context value only after controlled evaluation.

The deployed Lambda sets `PRA_EMBEDDING_PROVIDER=bedrock` and defaults to Amazon Titan Text Embeddings V2. Override the CDK context key `bedrock_embedding_model_id` to deploy with another Bedrock embedding model.

The deployed Lambda sets `PRA_VECTOR_STORE_BACKEND=faiss` and stores the active FAISS index plus vector metadata in S3. OpenSearch Serverless is not deployed by this stack so the MVP does not incur OpenSearch Serverless collection charges.

The stack also creates a CloudWatch dashboard and SNS-backed alarms. Set the alert email with the CDK context key `owner_email` or `aws_owner_email` when deploying if you want notifications routed to a different mailbox. If you do not set one, the stack uses the default configured in `pra_infra/stack.py`.

## Troubleshoot a Locked `cdk.out`

If CDK reports that another CLI is synthesizing to `cdk.out`, for example:

```text
Another CLI (PID=3480) is currently synthing to cdk.out.
```

First return to the terminal running CDK and press `Ctrl+C`. If that terminal is unavailable or the process is stuck, verify the process ID before stopping it.

PowerShell:

```powershell
Get-CimInstance Win32_Process -Filter "ProcessId=3480" |
  Select-Object ProcessId, Name, CommandLine

Stop-Process -Id 3480 -Force

Get-Process -Id 3480 -ErrorAction SilentlyContinue
```

Command Prompt (`cmd.exe`):

```cmd
wmic process where processid=3480 get ProcessId,Name,CommandLine

taskkill /PID 3480 /F

tasklist /FI "PID eq 3480"
```

Replace `3480` with the PID shown in the CDK error. Only stop the process after confirming that it is the stuck CDK, Node.js, or Python process for this repository. Do not delete `cdk.out` while a CDK process is still running. After the process exits, rerun the deployment from this directory:

```powershell
cdk deploy --require-approval never --force -c account=000000000000 -c region=us-east-1
```

```cmd
cdk deploy --require-approval never --force -c account=000000000000 -c region=us-east-1
```
